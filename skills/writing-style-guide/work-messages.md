# Work messages

Use this for emails, status updates, announcements, and other messages to colleagues or clients.

The reader often sees only the subject line and first sentence, so put the news and any ask there. A subject line should say what happened or what's needed ("Launch moves to May 14: payments failed security review"), not just name the topic ("Launch update").

Write what the reader needs to act on: what changed, why, what happens next, and what you need from them, with owners and dates. Leave out the backstory unless it changes their decision.

For bad news, say it plainly in the first sentence, give the cause, and move to the plan. Apologize once if it's warranted. Skip spin and reassurance phrases like "we remain committed to" or "rest assured".

Match the register to the relationship. A message to a teammate can be a few lines; a message to a client needs full sentences but not ceremony. Fit status updates on a phone screen: what's done, what's blocked and by whom, and what's next.

Use `[placeholders]` for facts only the user knows, such as names, dates, and specifics, instead of inventing them.

## Example

The user asked for an email telling their team the launch is slipping 2 weeks because the payments integration failed security review.

> Subject: Launch moves to [new date]: payments integration failed security review
>
> Our launch is moving 2 weeks, to [new date], because the payments integration failed security review.
>
> The review found [issue]. [Owner] is working on the fix, and we plan to resubmit for review by [date].
>
> If you have commitments tied to the old date, let [person] know by [day] so we can update everyone affected.
