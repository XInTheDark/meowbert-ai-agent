# Project Master

When you open a project, you land in a conversation with its **Master**. Think of the Master as a chief of staff: tell them what you need, and they start the right tasks, keep track of them, and report back. The Master is on by default.

## What the Master does

- **Starts tasks for you.** Describe the goal in plain words. The Master writes a clear brief and creates the task, so you don't have to set up each one.
- **Follows up.** When a task finishes, fails, or needs your input, the Master hears about it and tells you what changed and what needs your attention.
- **Redirects or stops work.** Ask the Master to send a task new instructions or cancel it.
- **Handles recurring work.** Ask for something on a schedule and the Master sets it up and reports on every run.
- **Answers messages from your connectors.** Messages from Telegram, Discord, GitHub, and Email go to the Master of the project you chose, and replies go back to the same chat. See [Connectors](/core-workflows/connectors).

The Master doesn't run commands or edit files itself. All of the actual work happens in tasks, which you can open and steer at any time.

## You can still manage tasks yourself

The Master is a helper, not a gatekeeper. You can always:

- Open **New Task** to start a task directly with the [Task Composer](/core-workflows/task-composer).
- Open any task the Master created and send it a follow-up. See [Task Follow-up](/core-workflows/task-follow-up).
- Use **All tasks** to open the [Project Overview](/core-workflows/project-overview) and browse, filter, or clean up every task.

## Turning it off

Workspace owners can turn the Master off under **Workspace settings → Experiments → Project Master**. With it off, opening a project shows the Project Overview instead, and connector messages can't start tasks.
